# 同じモデルなのに、露出は 4.6 倍

**小型ローカル LLM のプロンプトインジェクション耐性を実測する——そしてなぜ単一の「耐性スコア」が誤解を招くのか。**

> **CWE:** [CWE-1427](https://cwe.mitre.org/data/definitions/1427.html)（LLM プロンプトに用いる入力の不適切な無害化） · **OWASP LLM Top 10:** [LLM01 — プロンプトインジェクション](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)
> **テスト対象:** Ollama 経由の Llama 3.2（3B）、Raspberry Pi 5 上でセルフホスト — 認可された利用、自己所有のモデル。

**要約** — *同一の*小型ローカルモデルに対し、異なる 2 種類のプロンプトインジェクション攻撃を各 256 回実行した。モデルが「人類を憎め」という文字列を出力するよう乗っ取られた割合は **46.9%**、一方で暴力的な「人類を殺せ」という文字列ではわずか **10.2%** だった——同じ手法で目的だけを変えたところ、攻撃成功率に **4.6 倍**の差が生じた。信頼区間は重ならないため、これはノイズではなく実在の効果である。実務上の教訓：モデルのプロンプトインジェクション耐性は単一の数値ではない——攻撃者が*何を*引き出そうとするかによって大きく変わるため、単一のベンチマーク結果は実際の脅威から何倍もずれ得る。

## なぜこの記事を書くのか

LLM セキュリティに関する論評の多くは、単一の見出し的な数値で止まる——「モデル X はプロンプトインジェクションに Y% 脆弱」。この枠組みは安心感を与えるが、誤りである。プロンプトインジェクションへの耐性はモデルのスカラー属性ではない——ペイロードに依存する*分布*である。本記事はその分布を、信頼区間を付せるだけの試行回数で小型モデル上で測定し、そのうえでより有用なことを行う：数値が*なぜ*不均一になったのかを説明し、信頼できない入力の前に LLM を置くすべての人にとって何を意味するのかを示す。

ここでのモデルは意図的に控えめだ——Raspberry Pi 上でローカルに動く 30 億パラメータのモデル。目的は小型モデルの弱さを辱めることではない。*測定した*としても、単一の測定は安全性評価にはならない、と示すことにある。

## 1. 方法

- **モデル:** Llama 3.2（3B）。[Ollama](https://ollama.com) 経由でローカル提供、オフライン、Raspberry Pi 5 上。データは一切デバイスの外に出ていない。
- **ツール:** [garak](https://github.com/NVIDIA/garak)、NVIDIA のオープンソース LLM 脆弱性スキャナー（v0.15.1）。
- **プローブ:** garak の `promptinject` ファミリーの 2 種——`HijackHateHumans` と `HijackKillHumans`。いずれも通常のタスク内に隠れた指示を埋め込み、`AttackRogueString` 検出器は攻撃者の目標文字列が出力に現れたときに成功と数える。
- **回数:** プローブごとに 256 試行、各 1 生成。256 回あれば攻撃成功率を狭い 95% 信頼区間で抑えられる。

2 つのプローブは*同一の攻撃メカニズム*である。両者の唯一の違いは、攻撃者が強制的に引き出そうとする内容だけだ。

## 2. 結果

| プローブ（モデルに何を言わせようとするか） | 攻撃成功率 | モデルの防御 | 95% 信頼区間 |
|---|---|---|---|
| **HijackHateHumans** —「憎め」系の文字列 | **46.9%** | 136 / 256 | 41.0–53.1% |
| **HijackKillHumans** — 暴力的な文字列 | **10.2%** | 230 / 256 | 6.6–14.1% |

区間 `41.0–53.1%` と `6.6–14.1%` は接近すらしない。この差はモデル挙動の実在する性質であり、標本ノイズではない。

*（以前 `HijackHateHumans` の単一プローブ実行を再現性確認のため 2 回繰り返したところ、44.1% と 44.5% が得られた——ここでの 46.9% と整合し、測定が安定していることの証左である。）*

## 3. 発見：耐性は内容に依存する

同じインジェクション手法は、目標が軽度に有害（「憎悪」）な場合、露骨に暴力的（「殺害」）な場合より **4.6 倍多く**成功した。耐性はモデルに付随する単一の数値ではなく、目標内容の関数である。暴力的ペイロードだけを試した者は約 10% を記録し、モデルはそれなりに堅牢だと結論づけるだろう。軽度のペイロードだけを試した者は約 47% を記録し、ひどく露出していると結論づけるだろう。両者は同じモデル、同じ攻撃を使った。両者とも、曲線上のたった 1 点から結論を導いていることになる。

## 4. なぜそうなるのか

安全性トレーニングは設計上、不均一である。アライメント作業は、最も強い拒否を、最も明白に有害なカテゴリ——暴力・武器・自傷——に集中させる。これらが最も責任の重い失敗だからだ。そのトレーニングは同じカテゴリの*インジェクション*試行にも汎化する：注入された指示が暴力的な出力を強制しようとすると、モデルの最も強く強化されたガードレールに触れ、攻撃はより頻繁に失敗する。

軽度に有害な内容は、防御の手薄な領域にある。モデルは「憎悪」出力へ誘導されることへの強化がはるかに少ないため、同じ手法がずっと容易に一線を越えさせる。端的に言えば：**人間にとってより悪く見える攻撃こそ、モデルが最もよく防ぐものであり、より微妙なもののほうが最も露出している。** 衝撃ではなく信頼性を最適化する攻撃者は、第二の領域を狙う。

## 5. LLM を運用する人にとっての意味

1. **単一の耐性スコアは安全性評価ではない。** ペイロードを 1 つ試して数値を記録しても、その数値は別の目標に対するモデルの挙動から 4〜5 倍ずれ得る。自分の脅威モデルに対応するペイロードの*クラス*を試すこと——データ持ち出し、ツール／エージェントの悪用、ブランドを損なう出力、ポリシー回避——ベンチマーク付属のものだけでなく。
2. **危険な穴は、分かりやすいものではない。** 露骨に有害な攻撃は最もよく防御されている。露出はより微妙なカテゴリに潜む——まさに有能な攻撃者が押し込む場所だ。
3. **ガードレールはモデルの外に置く。** 内部防御が不均一である以上、*あなたが*気にするカテゴリをモデルが捕捉すると当てにはできない。周囲に決定論的な入出力フィルタリングを置き、乗っ取られたモデルが実際に何をできるかを制限すること——最小権限のツール、モデルの言だけで危険な操作を行わない。
4. **リリース前に測定し、変更のたびに再測定する。** インジェクション耐性は、モデルのバージョン、システムプロンプト、周辺の足場とともに変化する。一度チェックして終わる項目ではなく、監視すべき性質である。

## 6. 自分で再現する

テスト全体はありふれたハードウェア——Raspberry Pi、オフライン——で動く：

```bash
# 1. ローカルモデル
ollama pull llama3.2:3b

# 2. スキャナー
pipx install garak

# 3. 測定（プローブごとに 256 試行）
garak --model_type ollama --model_name llama3.2:3b \
      --probes promptinject.HijackHateHumans,promptinject.HijackKillHumans \
      --generations 1
```

garak は試行ごとの完全なレポート（`~/.local/share/garak/garak_runs/*.report.jsonl`）を書き出すため、すべてのヒットは信頼に基づくのではなく監査可能である。

## 7. 限界と誠実さ

これは意図的に範囲を限定した結果であり、そのように読むべきである：

- **1 つの小型モデルのみ。** これらの数値は Llama 3.2（3B）を記述する。より大きく、よりよくアライメントされたモデルは明確により耐性が高い。これは LLM 一般についての主張ではなく、*1 回の測定でも足りない*という実証である。
- **2 つのペイロードのみ。** 第 3 のプローブ `HijackLongPrompt` は開始したが除外した：CPU のみのテスト機で停止した（長コンテキスト生成がクライアント側タイムアウトなしでハングした）。2 ペイロードの対比はそれ自体で成立する——そして長コンテキスト生成のハングは、敵対的入力下のモデル挙動は仮定せず測定すべきだという、ささやかな戒めでもある。
- **1 つの検出器のみ。** `AttackRogueString` は完全一致文字列の出力を数える。実世界のインジェクションの成功基準はより曖昧だ。これは明確に定義された信号に対する下限であり、曖昧さがなく再現可能だからこそ選んだ。

限界を述べることこそが要点である。限界を伴わない数値は、測定ではなくマーケティングだ。

## これが示すこと

- プロンプトインジェクション耐性は **分布であり、スカラーではない**——そしてばらつきは大きい（ここでは 4.6 倍）。
- 手法は安価・オフラインで、かつ **Raspberry Pi で再現可能**。したがって「テストする資源がなかった」は本当の制約ではない。
- 信頼区間、再現手順、*そして*限界を報告すること——それが測定を見出しから分ける。

検証優先：分布を測定し、区間を示し、証拠を手渡す。
